# AGENT DIRECTIVES & SECURITY POLICY

## 1. Zero AI Fingerprints (Strict Attribution Scrubbing)
- Under no circumstances include AI-generated headers, signatures, or badges anywhere in the repository.
- NEVER write comments like:
  - `// Generated by AI`
  - `// Prompt: ...`
  - `// Added by assistant`
  - `/* Generated using Gemini / Claude / Cursor */`
- In `package.json`, `README.md`, or HTML templates:
  - Do not inject placeholder credits, AI tool badges, or default generative templates.
  - Set generic, professional metadata (e.g., author: repository owner, license: MIT).
- Write human-authored, idiomatic commit messages adhering strictly to Conventional Commits:
  - Format: `<type>(<scope>): <concise active-voice description>`
  - Examples: `feat(engine): add cidr subnet validation`, `fix(canvas): correct edge re-render on node delete`
  - Never commit with messages referencing agents, models, prompts, or automated passes.

## 2. Security Guardrails & Defense-in-Depth

### A. Secret Protection & Environment Hygiene
- NEVER hardcode API tokens, simulated credentials, private keys, or passwords in source code.
- If environment variables are required, load them strictly via `.env.local` or environment configs.
- Maintain a clean `.env.example` containing dummy key placeholders only.
- Never read, display, or stage `.env`, `.env.local`, `.pem`, or `.key` files in git.

### B. Client-Side Input Sanitization & Prototype Safety
- Validate all user-supplied input (IP strings, subnet masks, node names, MAC addresses) using a schema validator (Zod) before parsing.
- Enforce strict regex validation for network identifiers:
  - IPv4: Strict 4-octet `(0-255)` format; reject leading zeroes that trigger octal parsing.
  - CIDR: Strictly integer values `0` through `32`.
  - MAC: Strict 6-byte hexadecimal `XX:XX:XX:XX:XX:XX`.
- Block malicious payload injections in custom packet data:
  - Escape all user-defined payload strings prior to rendering on the canvas or DOM.
  - Avoid `dangerouslySetInnerHTML`, raw `eval()`, or dynamic `Function()` calls.
- Prevent prototype pollution during topology import/export:
  - Use `JSON.parse` with strict schema validation; do not use deep recursive merge without property whitelisting.

### C. Resource Exhaustion & Denial of Service (DoS) Prevention
- Enforce loop termination counters on the routing engine:
  - Hard cap maximum hop count (TTL <= 64). If hop count reaches limit, terminate simulation immediately with a dropped packet state.
  - Limit graph topology complexity: Maximum 100 nodes and 200 edges per simulation instance to prevent canvas freezing and CPU spikes.

## 3. Code Quality & Architectural Boundaries

### Tech Stack Standards
- **Framework:** React / Next.js (TypeScript strict mode).
- **Styling:** Tailwind CSS + shadcn/ui.
- **Topology:** `@xyflow/react`.
- **State:** Zustand (`store/networkStore.ts`).

### Modularity & Isolation
- Keep simulation algorithms completely decoupled in `lib/simulator/`:
  - Pure TypeScript functions only.
  - Zero imports from React, `@xyflow/react`, or UI libraries inside the simulator engine.
- Write unit tests alongside logic:
  - Every calculation in `lib/simulator/` must be paired with test cases covering edge cases (e.g., mismatched subnets, broadcast addresses, gateway unreachable).
- Avoid ghost packages:
  - Only import dependencies present in `package.json`.
  - Never generate imports for hypothetical third-party utilities.
